ECOPOINT. ПРИЛОЖЕНИЕ С ОБЩИМ БЭКЭНДОМ
Версия для GitHub и Netlify, 20 ноября 2026 года

ЧТО ВНУТРИ
В папке ecopoint находятся интерфейс, сервер, SQL-миграции и настройки сборки.
На Netlify используется общая PostgreSQL-база. На компьютере — SQLite.
В браузере остаются настройки интерфейса. Жалобы, отзывы, заполненность,
баллы, чеки и профиль хранятся на сервере.
Старые данные из автономных HTML-файлов и другого опубликованного сайта
в новую базу автоматически не переносятся.

1. РАСПАКУЙТЕ АРХИВ
Нажмите «Извлечь всё». Откройте папку ecopoint.
Внутри должны быть package.json, package-lock.json, netlify.toml, README.md,
START_HERE_RU.txt и папки src, scripts, netlify, drizzle, worker.

2. ЗАГРУЗИТЕ ИСХОДНИКИ В GITHUB
Для понятного начала создайте новый закрытый репозиторий ecopoint-final.
На GitHub нажмите + → New repository.
Repository name — ecopoint-final. Выберите Private → Create repository.
В пустом репозитории нажмите uploading an existing file.
Если уже есть файлы — Add file → Upload files.
Перетащите СОДЕРЖИМОЕ папки ecopoint с сохранением вложенных папок.
В корне GitHub должен оказаться package.json, рядом с ним netlify.toml.
Сам ZIP и внешнюю папку ecopoint загружать не нужно.
Нажмите Commit changes.

Если GitHub пропустит .gitignore или .env.example как скрытые файлы,
создайте .gitignore через Add file → Create new file.
Скопируйте его содержимое из архива. .env.example — пустой шаблон,
его можно добавить аналогично. Он не содержит действующего пароля.
Настоящий .env создаётся только при локальном запуске.

3. ПОДКЛЮЧИТЕ NETLIFY К ЭТОМУ РЕПОЗИТОРИЮ
Откройте https://app.netlify.com/ и войдите.
Выберите Add new project → Import an existing project → GitHub.
Разрешите Netlify доступ к ecopoint-final и выберите его.
Выберите ветку main.
Base directory — оставьте пустым.
Build command — npm run build
Publish directory — public
Functions directory уже задана в netlify.toml — netlify/functions.

Для этой сборки используйте импорт из GitHub: Netlify должен установить
зависимости, собрать интерфейс и серверную функцию, создать базу и применить SQL.

4. ЗАДАЙТЕ ПАРОЛЬ УЧЕБНЫХ АККАУНТОВ
Перед первым входом добавьте переменную окружения.
В форме импорта это Add environment variables.
После создания проекта — Project configuration → Environment variables
→ Add a variable.
Key — EP_BOOTSTRAP_PASSWORD
Value — придуманный вами отдельный пароль длиной 16–128 символов.
Область — Functions либо All scopes. Контекст — Production.
Если есть переключатель Secret / Contains secret values, включите его.
Сохраните пароль у себя и передайте преподавателю лично.
В GitHub, README и HTML его записывать не нужно.

При первой инициализации база создаёт пять учебных аккаунтов с этим паролем.
Позднее пользователь может изменить свой пароль через настройки.
Изменение EP_BOOTSTRAP_PASSWORD после первого входа не меняет
пароли уже созданных аккаунтов. Для смены собственного пароля используйте
раздел «Настройки» → «Сменить пароль» под ролью жителя.

5. СОЗДАЙТЕ DEPLOY И ПРОВЕРЬТЕ БАЗУ
Запустите Deploy и дождитесь статуса Published / успешного завершения.
База должна создаться автоматически: в архиве есть @netlify/database
и миграция netlify/database/migrations/0001_ecopoint.sql.
Откройте Data & Storage → Database.
Если базы нет, выберите Create a database manually, затем повторите Deploy.
Схема и учётные записи создаются без ручного редактирования SQL.
Если переменные добавлены после сборки, запустите новый Deploy.

Netlify Database доступна на credit-based plans и расходует кредиты.
По условиям курса используйте доступный бесплатный вариант без банковской
карты. Если Netlify требует платный тариф или карту, используйте localhost
по пункту 9. Публикация не даёт дополнительных баллов по условиям курса.

6. ОТКРОЙТЕ ПРИЛОЖЕНИЕ
Возьмите адрес сайта из Netlify и откройте в браузере.
Логины:
Житель — resident@example.test
Второй житель — resident2@example.test
Коллектор — collector@example.test
Менеджер — manager@example.test
Администратор — admin@example.test

Начальный пароль для всех пяти — значение EP_BOOTSTRAP_PASSWORD,
которое вы сами задали в пункте 4.
Роль определяется сервером по аккаунту.
Коллектор обслуживает все семь станций.
Учебный менеджер работает со станциями ES-1, ES-2 и ES-3.
Рядом с паролем есть «Показать» / «Скрыть».
Язык можно выбрать перед входом.

7. ПРОВЕРЬТЕ ОБМЕН МЕЖДУ УСТРОЙСТВАМИ
На обоих устройствах откройте один и тот же адрес Netlify.
На первом войдите как житель, на втором как администратор.
Житель: «Настройки» → «Помощь и поддержка» → отправить обращение.
Администратор: «Обращения» → «Активные» → ответить → «Решено».
Житель увидит ответ и статус. Закрытые заявки доступны в «Решено».

Выберите станцию на карте, подтвердите её QR или деморежим без камеры,
нажмите «Имитировать загрузку». Штуки, граммы и баллы рассчитает сервер.
Нажмите «Далее» для чека. Чек можно скачать и снова открыть из истории.
У другого пользователя заполненность этой станции увеличится.

Войдите коллектором, выберите ту же станцию и нажмите «Обслужить терминал».
Подтвердите правильный QR или деморежим и вывоз.
Через несколько секунд в другом браузере заполненность станет 0%.
Обновление обычно происходит раз в 5 секунд.
Во время заполнения формы или открытого окна операции обновление
откладывается, чтобы сохранить введённые данные.

8. ПЕРЕДАЙТЕ ДОСТУП ПРЕПОДАВАТЕЛЮ
Добавьте ссылку Netlify в поле Website в GitHub → About → шестерёнка.
В README перечислены логины. Пароль передайте отдельно.
Если GitHub закрытый, добавьте преподавателя в Settings → Collaborators.
По условиям курса прототип должен быть доступен только команде
и преподавателю: используйте Private / ограничение доступа Netlify.
Проверьте Project configuration → General → Visitor access → Project visibility.
На Credit-based Free/Personal закрытый сайт виден только владельцу Netlify.
Приглашение других посетителей в закрытый проект требует Pro.
Для демонстрации преподавателю без платного плана используйте localhost.
Если нужна доступная по ссылке закрытая демонстрация на бесплатном плане,
сначала согласуйте способ доступа с преподавателем.
Для бесплатного локального показа используйте пункт 9.
Форма входа приложения и доступ к самому сайту — отдельные настройки.

9. ЗАПУСК НА КОМПЬЮТЕРЕ
Установите Node.js 24 или новее с https://nodejs.org/.
Откройте терминал в папке ecopoint и выполните по очереди:
npm ci
npm run setup
npm run build
npm run dev

Откройте http://localhost:5173
Для входа используйте логины из пункта 6.
Локальный пароль автоматически записан в .env в папке ecopoint.
Посмотреть файл можно в Блокноте. Не показывайте его на видео.
Локальные данные сохраняются в .data/ecopoint.sqlite.
Остановить сервер — Ctrl+C.
Чтобы запустить повторно, достаточно npm run dev.
Для автоматической проверки — npm test и npm run check.
Локальный сервер по умолчанию доступен только на вашем компьютере.

10. ЕСЛИ НЕ РАБОТАЕТ
404 на главной — проверьте Publish directory public и команду npm run build.
Сообщение о базе — проверьте Data & Storage → Database и успешную миграцию.
«Администратор должен настроить учебные аккаунты» — проверьте
EP_BOOTSTRAP_PASSWORD, область Functions и повторите Deploy.
«Неверный логин или пароль» — вводите значение, заданное при первом запуске.
Если житель менял пароль, используйте его новый пароль.
Проверьте, что оба устройства используют одинаковый адрес сайта.
Проверить сервер и подключение к базе можно по адресу сайта плюс /api/health.
При рабочем подключении ответ содержит ok: true и storage: PostgreSQL.
При проблеме подключения /api/health вернёт ошибку 503.
Статус initialized: false до первого входа допустим.
